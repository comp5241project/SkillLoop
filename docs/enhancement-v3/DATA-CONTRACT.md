# Enhancement v3 data contract

The new teacher and learner UI lives at /enhancement-v3/web/. Part 2 is **Case Learning / AI Personalized Learning**. The filesystem name knowledge-map is a legacy route used only to continue to the existing canonical Case Learning activity. v3 uses no Knowledge Map data, graph UI, graph API, or ownership model.

- **Course session:** All v3 operations use /api/courses/?op=v3-…, so the existing HttpOnly course cookie is sent to the same path. Supabase validates the bearer, and course transactions set the existing non-BYPASSRLS database role and actor. Mutations require an exact same-origin request and X-SkillLoop-Course: 1.
- **Private sources:** A v3 draft owns one immutable extraction, split into stable s1, s2, … fragments with page, paragraph or HTTPS excerpt locators. The source filename, raw extracted text, and exact quotes live only in the teacher-owned draft. Upload bytes are processed in memory and discarded. File limit is 3 MB, extract limit 16,000 characters, PDF page limit 50, and DOCX cumulative uncompressed size limit 15 MB. URL fetching validates all DNS answers, pins the actual socket IP, rechecks up to three redirects, and bounds response size and duration. There is no OCR, login JavaScript execution, or retrieval of embedded document links.
- **Draft and publish:** Every save, rematch, and selection invalidates approval on change. Optimistic revisions prevent a stale tab from overwriting saved edits, including long-running AI requests. Publication revalidates source citations and case coverage against the current trusted registry. An approved hash names the exact student preview. The reviewed M4 snapshot and the v3 snapshot share the same course UUID/version, and are written in one transaction using M4's validated save, review and publish functions. A repeated publish for the same revision is idempotent. The case is fixed for the lifetime of that course; to change it, create a new course. The teacher can publish changed notes and objectives as a new version with the same case.
- **Public views:** Catalog returns title, overview, objectives, case identity and latest release metadata (up to 100 courses). Course overview returns approved lesson notes, sanitized citation locators and mapping, never the private extract/quotes. Earlier published versions remain addressable. Legacy M4 publications can be browsed, but have no v3 notes or generation.
- **Personalized teaching:** v3 reads only the logged-in learner's owned attempt and persisted diagnosis. The cache key hashes attempt, pinned version, content hash, case version, diagnosis evidence, and prompt protocol. It cannot be set by a client, and changing the diagnosis requires a new key. Only the mapped teacher notes, canonical requirement and public trace, and the authored diagnosis question/selected answer go to the model. Free-form diagnosis explanation and other learner records are excluded. A practice answer is saved before feedback; provider errors leave it available for retry. Neither coaching nor feedback writes official stage progress.
- **AI boundaries:** The configured AI_* provider is used for notes, matching, teaching, and feedback. No production mock or automatic fabricated result. Output is checked against schemas, exact extracted quotes, eligible candidate identities, approved note IDs and diagnostic targets. Exact quotation validation establishes traceability; the teacher still checks semantic accuracy, contradictions and coverage before publishing. Helpfully worded AI feedback is coaching, not scoring or executable verification. Each signed-in actor has one durable concurrent request lease and a UTC hourly limit of 24 calls; no network calls inside a SQL transaction. The system does not automatically retry paid model requests.
- **Failure and recovery:** Import errors do not create drafts. AI failures leave the extract and edits intact. Lesson failures display teacher-approved notes and a separate retry action. Session errors do not send anonymous clients to protected records. Clear expired sessions by signing in again.

## Setup

Use Node 22+ and install the locked dependencies with npm ci. Apply the additive v3 migration in sequence to the target database before rolling out this branch's server. It is tested on a disposable PostgreSQL cluster; it has not been applied to a hosted project. Set SKILLLOOP_COURSE_DATABASE_URL to the same restricted runtime login used by M4, SUPABASE_URL and SUPABASE_PUBLISHABLE_KEY for existing account login, and AI_BASE_URL, AI_API_KEY, AI_MODEL for live generation. No new credential, browser key, stage API, or hosted write is needed to run the local tests.

The course API requires the migrated schema for v3. A rollback to v2 code preserves both the old course tables and new v3 release/attempt records. Keep the migration in place to preserve published lineage; audit the v2 teacher Studio handling of v3 backing courses before serving old code to users after a v3 launch.
