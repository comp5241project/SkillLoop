# Knowledge v0.4 implementation status

Updated 2026-10-27 on `feature/knowledge-map`. This records implementation evidence, not a release claim.

## Implemented locally

- Unit-first Teaching Studio with a manual path and a Discover template outline. Teachers can select, edit, merge and explicitly confirm Directions in one atomic database operation before AI graph generation. Direction Graph editing uses a canvas and concept inspector; the historical independent Graph Studio remains available. A teacher can explicitly confirm copying one of their published Independent Graphs into a new Direction Graph draft; the target keeps its own ID/version history and an origin reference, and existing target edits are preserved. A teacher can also explicitly copy an individual concept from an owned published Direction Graph Version into a local Graph draft, with a new local ID and source-version provenance; original evidence references are cleared for review in the target Unit.
- Two-stage AI proposals: source/topic planning, then Unit sections, Direction Graphs and learning activities for confirmed Directions. Generation uses at most three confirmed Directions per job; a pending batch must be accepted or dismissed before starting another, so accepting one batch cannot silently stale another. Proposals record model, prompt/schema version and captured source snapshot references. They are private and must be explicitly added to drafts. The proposal card previews content and graph structure before batch acceptance; teachers can accept Unit sections, learning activities, concepts and relationships separately, or dismiss a proposal. Accepted Graph items merge into existing drafts by ID without replacing teacher edits. The publish page previews Unit content and the selected fixed Graph Version. Local item regeneration keeps the original until accepted. Review is by Unit/module with optional item editing.
- Separate Unit and Direction Graph draft/version identities. Publication accepts existing Graph Versions or publishes new Graph Versions with the Unit in one Postgres transaction. Studio defaults to reusing the latest published Graph Version and lets teachers choose older versions or explicitly publish a draft as new. Unfinished planned Directions can remain private; a published Unit Version contains only Directions with fixed Graph references. Each Graph Version freezes its own source metadata so it remains readable and reusable even if a later Unit draft changes its sources. Historical Unit Versions keep fixed graph references. Teachers can withdraw a selected Unit or Graph Version with a reason. Unit withdrawal leaves an unwithdrawn Graph Version readable under its own identity. Withdrawing a Graph Version atomically withdraws Unit Versions that reference it, so public links show notices instead of broken Direction links; later publication uses new version numbers.
- HTTPS source capture with bounded content and pinned DNS address. GitHub capture fixes a commit and samples its README when available and bounded source files at that commit, excluding repository agent-instruction files; article capture records retrieval time. Each stored snapshot records its sampled scope and SHA-256 content fingerprint, and the scope is shown in Studio and public reading. Source metadata and evidence references are separate from AI prose. Captured source and AI proposal records are written only by the server role. Manual sources remain teacher asserted and marked separately.
- Discover retains the v0.3 static catalog. From Teachers reads formally published teacher Units, with filters, a Unit detail page, fixed Direction Graph reading, source metadata and a withdrawal notice. Both channels use `reader-components.js` for the Unit hero, article/direction layout and Graph selection details while keeping their separate source and publication rules. Captured sources can optionally be marked reviewed by the teacher; a review date is displayed only after that action and is not a publication gate. Captured articles retain publisher, publication date and same-origin canonical URL when present.
- Vercel Queues consumer for the single machine stage of each AI task. Job/Proposal state is stored in Postgres. Queue redelivery reuses an existing proposal, and an interrupted running job can be reclaimed after its lease window. In local development, the same job runner executes synchronously so a linked Vercel Queue is not required.
