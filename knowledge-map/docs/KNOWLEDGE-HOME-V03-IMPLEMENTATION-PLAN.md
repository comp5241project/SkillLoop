# Knowledge Home v0.3 实施计划

**状态**：用户已在 2026-10-26 明确批准执行 v0.3；实现位于 `feature/knowledge-map`，尚未合并。
**分支**：`feature/knowledge-map`。
**范围**：Knowledge 模块的静态精选内容、公开阅读体验、局部图谱和针对性验证。v0.4 以本版的数据契约与读者体验为前置条件。
**产品基线**：本地修订文档 `SkillLoop_Knowledge_Home_v0.3_Plan_Revised.docx`。仓库内的实现仍须以当前工作树为准；已有未提交的页面与导航编辑不得覆盖。

## 1. 目标和完成定义

把 `/knowledge-map/` 从概念优先入口改为 **Exploration Unit 优先**的公开探索页。访客从真实项目、事件、实践或知识集合提出的问题出发，读懂 Unit 本身，再按需要进入局部知识方向和来源。教师共享图谱与现有公开目录继续可用，但位于首页次要区域。

v0.3 交付四篇由项目团队人工整理、核查的 Unit，分别覆盖 Open-source Breakdown、Case Study、Build Something、Knowledge Collection。每篇至少有一个可阅读、有来源的知识方向；一个方向对应一张独立的静态精选图谱。Excalidraw 无限画布是开源项目篇的优先候选，但只有仓库修订版、代码位置及具体方向可核实时才纳入。不能核实的方向不展示。

本版**不**实现抓取、LLM 分析、教师 CMS、教师发布流水线、Supabase 迁移、Unit 收藏、静态节点加入个人图谱或自动去重。`Save to My Knowledge` 等未来动作可以保留禁用状态和解释，不得暗示保存成功。现有账户与教师功能只做回归保护。

## 2. 现有代码边界

- `knowledge-map/home.js` 当前搜索仓库自带的七概念样例，并把公开图谱放在首页主区；`index.html` 承载该入口。首页已有未提交的命名调整，实施时先检查并保留。
- `knowledge-map/network-core.js` 的公开图谱加载先请求 `/api/knowledge?op=public`，只为原样例图提供静态兜底；`Canvas` 可复用交互，但不能直接把新静态图谱伪装成教师发布图谱。
- `api/_knowledge-model.mjs` 的发布图谱验证要求完整课程字段，且只接受现有四种关系类型。方向图谱需要精简的、独立验证的静态内容契约；v0.3 不改变现有教师图谱 API 或数据库格式。
- `reference` RPC 只接受 Supabase 中已发布的概念。新静态节点只能阅读与导航，不能调用它写入 My Knowledge。
- `/knowledge-map/?topic=...`、`graph.html`、`concept.html`、`question.html`、`case.html` 和 `version=` 历史链接已有外部或跨模块使用者，必须保留行为。

## 3. 静态内容契约

建议在 `knowledge-map/` 下设独立的版本化内容目录及纯浏览器可加载的 JS 数据模块。仓库没有前端构建步骤，不能仅提交浏览器无法执行的 TypeScript。可用 JSDoc 定义类型、使用独立校验模块验证数据，并保持数据与渲染分离。正式文件名在实施时依据现有目录确定。

### 3.1 Exploration Unit

| 字段组 | 最低要求 |
| --- | --- |
| 身份 | `schemaVersion`、稳定 `id`、`slug`、不可变 `version`、`status`（active 或 withdrawn）、`latestVersion` 由目录索引维护 |
| 发现 | 四种 `type` 之一、`title`、`hook`、`guidingQuestion`、`summary`、`level`、`topics[]`、`estimatedMinutes`、精选排序 |
| 阅读 | 带类型的 `sections[]`；可按内容类型调整顺序和布局，不强制相同正文模板 |
| 证据 | `sources[]` 指向受控来源目录；事实陈述、代码位置和图谱事实可追踪到来源；解释性内容明确标记 |
| 探索 | 非空 `directions[]`，每项包含稳定方向 ID、图谱 ID、固定图谱版本、标题、摘要、排序与首页是否精选 |
| 编辑 | 项目团队核查记录、`checkedAt`，必要的来源发布日期、仓库 commit SHA 和核对位置 |

Unit 自身必须回答具体问题，即使方向图谱暂时不可读也能完成阅读。`directions[]` 不要求统一数量；展示出来的每个方向都必须真实可用。一个 Unit 的实质内容变化或方向所指图谱版本变化，生成新的 Unit Version，不能覆盖旧版。

### 3.2 方向图谱

每个方向图谱有稳定、图谱范围内的 ID、不可变版本、所属 Unit／方向及来源。节点至少有稳定 ID、标题、简述、来源引用；可选 `contextNote` 写明该概念在当前案例中的特点。不同方向可分别解释同一主题，使用显式跨方向链接；v0.3 不创建全站概念身份合并器。

关系至少包含稳定 ID、起点、终点、读者可见的名称、解释、`basis`（`source-supported` 或 `teaching-association`）及相应来源引用。前者必须有可核查材料，后者解释教学价值，不表述成材料证明的因果或技术依赖。暂不冻结 `depends on`、`implements` 等完整语义词表或推理规则。节点与关系的文字均作为不可信数据安全渲染。

来源目录应保存稳定 source ID、HTTPS URL、标题、发布者、材料类型、`verifiedAt`；按材料可附发布日期、授权／使用说明、仓库 revision SHA、已核实文件路径及位置。引用位置只能针对被核实的固定修订版，不能生成未经检查的行号。

### 3.3 版本与撤回

- 目录索引显式指向每篇 Unit 的最新版；Home 只读取索引，不通过数组顺序猜测版本。
- Unit Version 固定到每个方向的 Graph Version。旧版 Unit 和图谱保持只读；访问旧版时提示新版并提供主动跳转，不自动切换。
- 固定图谱版本不可用时显示明确错误，可提供“查看最新版”操作，但不得悄悄替换。
- 已知严重错误或授权撤回时，历史 URL 返回说明原因与替代版本的 tombstone，不继续展示问题正文。
- 稳定 ID、版本及来源字段为 v0.4 的导入与正式发布保留映射基础；本版不实现转换工具。未来若 ID 冲突，必须记录映射并维护历史链接。

## 4. 页面与数据流

1. **Home**：以四篇 Unit 的卡片和精选排序为主体，展示类型、问题、具体预览、主题、来源身份；支持类型与主题筛选。教师共享图谱和当前公共图谱目录放在清楚但次要的位置。旧 `?topic=` 进入现有概念页的跳转优先执行。
2. **Unit detail**：建议独立静态页 `/knowledge-map/unit.html?unit=<id>&version=<version>`；无 `version` 时解析目录索引的最新版。页面根据 section 类型灵活呈现 Overview、Artifact／Source、How It Works／Evidence、Knowledge Directions 和 Learning Activities。所有方向可访问；首页或首屏可先突出代表性方向。
3. **Direction detail**：建议 `/knowledge-map/direction.html?unit=<id>&version=<unitVersion>&direction=<id>`。从固定 Unit Version 解析固定 Graph Version，再显示局部图谱、节点上下文特点、关系解释及来源，并链接回该 Unit Version。单独设计数据适配层后复用现有画布能力；避免将图谱数据直接塞进旧发布图谱 API。
4. **个人操作**：静态节点与 Unit 的保存、引用、迁移按钮禁用并给出说明；不发写请求、不写私人 localStorage。若页面还包含现有正式发布图谱链接，其旧功能仍由原页面处理。
5. **错误状态**：处理未知 Unit、未知版本、方向缺失、来源链接被移除、图谱数据校验失败和撤回版本；任何失败不得显示空白画布或静默跳到另一版。

以上路由是实施建议，最终路径以不破坏已有 deep links 为原则。新页保持相同来源策略；不将未经审核的网络内容插入 HTML，不执行仓库代码。

## 5. 实施顺序和交付物

| 阶段 | 工作 | 验收门槛 |
| --- | --- | --- |
| 0 — 证据与内容清单 | 确定四篇选题、原始来源、核查日期、每篇至少一个方向；对 Excalidraw 固定并核实仓库修订版 | 不写未经核实的技术结论；每个方向有明确教学问题与材料 |
| 1 — 契约与校验 | 建立 Unit、Graph、Source 的静态数据结构和校验；造一篇 Unit 的 V1/V2 用于历史链接验收 | 重复 ID、断裂引用、无来源的事实关系、错误版本均被检出 |
| 2 — 阅读器 | 实现 Unit 与 Direction 详情、图谱适配、来源和版本状态、返回精确 Unit Version | 四篇正文可独立阅读；每篇至少一张可用方向图谱 |
| 3 — Home | 改造 Unit 卡片、类型／主题筛选与精选排序；教师共享区降优先级 | 匿名读者从首页能区分内容并打开目标 Unit |
| 4 — 验证 | 检查四篇内容、响应式与键盘操作、旧链接、账户／教师回归、模拟与连通环境差异 | 无断开的内部链接；历史、不可用、撤回状态可见；未引入私人数据写入 |

阶段 0 的来源选择须先形成可审查的材料清单。不得把“候选案例”或示意 UI 文案当作已核实的 Excalidraw 技术事实。

## 6. 检查与验收

**自动检查**：为静态契约建立针对性测试，覆盖四种内容类型、最少一方向、稳定 ID、版本索引、图谱端点、来源 HTTPS、事实关系证据、教学关联理由、无效链接与撤回。扩充站内链接检查；保持现有 `npm test` 通过。测试输出区分静态 fixture、模拟 API 与真实连接服务。

**阅读任务**：匿名访客从 Home 识别并选择内容，解释 Unit 的核心问题和依据，进入任一方向，读懂节点与关系为何相连，再打开原始来源；全过程无需登录。逐项检查四篇内容、手机宽度、键盘与屏幕阅读器语义、加载／空结果／不可用状态。

**兼容检查**：原样例与教师共享目录继续可访问；旧 `?topic=` 与 `graph/concept/question/case` 深链及历史 `version=` 行为保持。现有账户和教师页面不被新静态图谱改写；不以新静态节点测试尚未实现的个人引用。
