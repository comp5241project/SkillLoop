**Version:** 0.1<br>
**Date:** 2026-10-22<br>
**Status:** Proposed Implementation Baseline<br>
**Scope:** Knowledge Module — Student, Public Content, Teacher Workspace<br>
**Primary Reference:** ARCHITECTURE-UX-AUDIT.md (2026-10-22)

# 1. 项目背景与重构目标

## 1.1 当前问题

根据代码与线上页面审计，Knowledge 模块存在以下结构性问题：

- 个人图谱、公开学习内容、教师内容制作和账户管理缺乏明确的导航边界。
- 新用户进入个人知识空间时，首先面对空图谱和账户操作，缺少合理的入门流程。
- 节点、关系、笔记等操作缺少一致的上下文交互模式。
- 图谱连线不可直接选择，关系无法作为完整的学习对象被探索。
- 已存在的关系判断活动和跨模块练习入口未完整呈现。
- 教师案例编辑存在覆盖未显示字段的风险。
- 草稿切换、保存失败和账户不可用等状态反馈不完整。
- 前端文件承担过多职责，阻碍独立维护和增量开发。

## 1.2 重构目标

本轮重构需要达成以下目标：

**G1 — Clear Information Architecture**

用户能够区分个人知识空间、公开图谱资源和教师工作区。

**G2 — Graph-Centered Exploration**

图谱成为知识探索的主要交互界面，节点与关系都能通过统一的上下文详情查看。

**G3 — Progressive Disclosure**

根据当前任务和选中对象提供必要操作，避免同时展示大量编辑表单。

**G4 — Complete Learning Flow**

公开图谱的概念、关系、练习、案例与个人引用构成完整的学习流程。

**G5 — Safe Editing**

所有编辑操作应具备明确的保存、取消、失败恢复和未保存变更保护。

**G6 — Compatibility**

不破坏已有数据、已发布内容、教师所有权、个人引用及跨模块链接。

## 1.3 非目标

本轮不实施：

- 前端框架迁移或整体技术栈重建。
- 全新的知识图谱数据模型。
- 自动知识融合。
- 完整的 AI 个性化推荐引擎。
- 全平台学习路径重构。
- 复杂图谱自动布局算法。
- 复杂的内容版本合并与同步。
- 全新权限体系。
- 无审查的大规模 AI 内容生成。

# 2. Open Product Decisions — 最终建议

以下逐项回应审计报告中的七个开放问题。

## D01 — Knowledge 默认入口

**Decision: Contextual Personal Workspace**

Knowledge 默认进入个人知识空间，但依据用户状态呈现不同内容。

### A. 新用户或个人图谱为空

显示引导型 Empty State，包括：

- 简短说明个人知识网络的用途。
- 主要操作：Explore Knowledge。
- 次要操作：Try Sample Graph。
- 若有可引用资源，允许从示例或公开图谱中引用第一个概念。
- 允许直接创建个人节点，但不将其作为首次使用的唯一或主要任务。

不将空图谱画布、账户表单和复杂编辑器直接作为首屏核心内容。

### B. 已有个人知识节点

默认显示个人图谱。

页面保留当前知识网络的浏览状态和必要操作入口。根据实际实现能力恢复上一次使用的视图，无法恢复时安全地显示完整图谱。

### C. 未登录或后端未配置

允许使用已有浏览器本地功能。

明确显示 Local Mode 状态，但不阻断静态示例探索。

不可用的账户操作不得表现为可正常执行的功能。

**Rationale:** 保留个人网络作为 Knowledge 的核心，同时降低初次使用成本。

## D02 — 是否提供公开图谱目录

**Decision: Yes — Lightweight Explore Directory**

建立公开知识资源探索入口 Explore。

首版展示：

- 已发布且可公开读取的图谱。
- 图谱标题与简要描述。
- 发布者信息（在现有数据允许的范围内）。
- 关联主题与概念数量（仅在可可靠取得时显示）。
- 浏览图谱入口。
- 七概念示例资源。

公开目录的内容必须来自真实可公开访问的数据或明确标记的静态示例。

不得泄漏教师私有草稿。

如现有 API 不支持枚举公开图谱，可增加最小只读发现接口，但必须先检查现有数据库权限与 API 契约。

**Rationale:** 避免非示例资源只能依靠外部分享链接才能被发现。

## D03 — 个人引用的关系版本语义

**Decision: Preserve Existing Semantics in This Refactor**

本轮保留当前数据契约：

- 个人引用保存来源图谱 ID、概念 ID、来源版本及内容快照。
- 已发布的教师历史版本不可变。
- 当前个人图谱中的教师关系读取语义暂不改变。
- 不自动转换为固定版本关系，也不自动升级历史引用。

需要在 UI 中区分：

- 引用的概念来源版本。
- 当前显示的公开图谱版本（如可获取）。
- 个人手动创建的关系。

当二者版本不一致时，提供简明说明，不将当前关系错误地标记为历史版本中的确定关系。

如果当前实现无法可靠得知关系来源版本，应避免显示可能误导用户的版本标签。

将“关系固定版本或跟随最新发布”作为未来的独立产品决策。

**Rationale:** 防止 UX 重构意外改变知识引用和同步规则。

## D04 — 关系详情与编辑形式

**Decision: Interactive Edges + Context Panel**

关系成为可直接选中的图谱对象。

用户点击连线或关系列表项后，打开统一的 Relationship Detail Panel。

显示：

- 起始节点。
- 目标节点。
- 关系类型。
- 关系方向。
- 连接理由。
- 来源归属。
- 在已有数据支持下显示相关学习说明。

### 学生权限

对于引用的教师关系：

- 允许阅读和探索。
- 不允许直接修改教师原始关系。
- 可创建自己的补充关系。

对于个人手动关系：

- 允许创建、编辑理由、修改关系类型（前提是数据模型支持）、删除。
- 操作需要确认和失败恢复。

### 教师权限

教师可在自己的草稿中创建、修改、删除关系。

已发布版本保持不可变，修改应进入草稿与再次发布流程。

### 交互方式

默认通过侧栏处理，不为普通关系创建独立详情页。

移动端可使用 Bottom Sheet 或覆盖式详情面板。

已有关系类型如未提供结构化枚举，不得凭 UI 假设直接写入任意新类型。实施前应核对现有模型校验规则。

## D05 — activities 与 practiceHref

**Decision: Restore Visible Access**

已有活动与跨模块练习属于应保留的学习功能。

### activities

在相关概念、图谱或关系详情下提供 Learning Activities 入口。

根据活动的原有数据关联方式决定显示位置，不强行把所有活动变为节点级内容。

### practiceHref

在概念详情中显示 Practice / Continue Practicing 操作。

必须沿用现有 URL 契约，不自行生成不兼容的链接。

### 交互要求

- 用户可以明确区分学习材料、测验和实际练习。
- 维持原有练习即时反馈行为。
- 自报学习标记不等同于测验通过。
- 不将本地练习结果伪装成服务器保存的成绩。

**Rationale:** 恢复已有能力，避免重构期间发生功能回退。

## D06 — 教师复杂内容编辑策略

**Decision: Lossless Editing First**

任何编辑页面不得因为未显示部分字段而丢弃现有数据。

对案例中的多条 claims、links 以及概念中的路径字段：

1. 可在本轮实现的字段，提供完整的结构化编辑器。
2. 暂时不能编辑的字段，至少提供只读展示或清晰的存在提示。
3. 保存其他字段时，必须无损保留未编辑字段。
4. 对会引发结构变化的操作，必须明确提示。

对于多条 claims 与 links，优先实现列表式增删改，而非只编辑第一项。

对于 `pathRole`、`order`、`icon` 等路径相关字段，可在本轮保留原值，路径排序 UI 暂不扩展。

需要通过自动化测试验证多条内容在编辑后没有丢失。

**Rationale:** 数据完整性优先于编辑器视觉简洁。

## D07 — 浏览器记录导入失败

**Decision: Explicit, Non-Destructive Import**

用户需要主动触发浏览器记录导入。

导入前展示：

- 可尝试导入的记录数量。
- 目标账户。
- 可能重复或不兼容的记录（在现有接口能够识别的范围内）。

当遇到来源未发布、历史版本缺失或服务端拒绝时：

- 告知具体失败原因。
- 保留原本的浏览器记录。
- 不伪装成成功导入。
- 允许用户稍后重试。
- 对可重试与不可重试错误作出区分。

不得在未确认数据可恢复前自动清除本地内容。

如原有导入 API 为全量事务操作，UI 不应声称支持逐条部分成功。

**Rationale:** 保证个人知识资产不会因登录和数据迁移而意外丢失。

# 3. Information Architecture

## 3.1 全局定位

Knowledge 是 SkillLoop 全局导航中的一个主要工作空间，与 My Path、Interview、Correction Lab 保持现有关系。

Knowledge 内部提供以下主要区域：

1. My Knowledge — 个人知识空间。
2. Explore — 公开图谱和学习主题探索。
3. Teacher Workspace — 教师专属创作管理入口。
4. Account / Data Management — 放入全局账户菜单或相关设置位置。

Teacher Workspace 是角色功能，不作为普通学生的一级知识资源。

如当前用户角色无法从现有身份服务可靠识别，不得仅依靠客户端隐藏按钮作为权限控制；仍应由后端验证权限。

## 3.2 推荐页面结构

```text
SkillLoop
├── Knowledge
│   ├── My Knowledge
│   │   └── Personal Graph Explorer
│   ├── Explore
│   │   ├── Public Graph Directory
│   │   ├── Public Graph Explorer
│   │   ├── Concept Learning View
│   │   └── Activities / Cases
│   └── Teacher Workspace [Teacher role]
│       ├── Graph Library
│       ├── Draft Editor
│       ├── Preview
│       └── Publish
├── My Path
├── Interview
├── Correction Lab
└── Account / Settings
    └── Data & Import
```

## 3.3 路由策略

保留现有有效路径及其参数：

- `/knowledge-map/`
- 公开图谱 `graph` 参数。
- 概念 `topic` 参数。
- 练习 `question` 参数。
- 案例 `case` 参数。
- 历史发布 `version` 参数。
- 旧 `/knowledge-map/?topic=...` 重定向。

可以新增 Explore 页面和账户设置入口，但不能使现有深链接失效。

不得为了统一页面风格而一次性改写所有 URL。

由 Codex 根据现有静态页面部署方式提出最小增量路由实现。

# 4. Graph Explorer 交互设计

## 4.1 页面布局

桌面端建议采用：

**Global Navigation + Graph Toolbar + Graph Canvas + Context Panel**

### Graph Toolbar

包含：

- 当前图谱或主题名称。
- 图谱来源和类型标识。
- 搜索。
- 聚焦 / 重置视图。
- 根据权限显示 Add 操作。
- 必要的主题或视图切换入口。

### Graph Canvas

承担：

- 节点呈现。
- 类型化关系呈现。
- 视口平移、缩放。
- 节点和关系选择。
- 聚焦与定位。
- 已有拖拽布局能力（仅在允许编辑位置的上下文）。

### Context Panel

根据选择状态呈现：

- 未选择：当前图谱简介或使用提示。
- 选择节点：Node Details。
- 选择关系：Relationship Details。
- 触发编辑：对应编辑器。
- 触发 AI 操作：预览和确认状态（仅适用于已实现功能）。

详情面板保持图谱上下文，不要求浏览器整页跳转。

## 4.2 Node Details

推荐内容层级：

1. Title & Type
2. Description / Overview
3. Relationships
4. Learning Resources & Activities
5. Personal Notes（个人空间适用）
6. Source & Version
7. Contextual Actions

以上不表示所有内容必须以标签页展开。应根据内容密度采用自然分组和渐进披露。

不要为了制造视觉层级而加入大量嵌套 Tabs。

## 4.3 Relationship Details

用户选中一条边后应能回答：

- 它连接哪两个知识概念？
- 它是什么类型的关联？
- 为什么存在这种关联？
- 关联是教师提供还是用户自己建立？
- 当前用户是否能够修改它？

如果节点太密集，点击连线困难，允许通过关系列表选择对应边。

边需要具备足够可选中的交互命中区域，视觉线宽不必因此明显增加。

## 4.4 搜索和定位

搜索输入后应：

- 在结果列表中呈现匹配节点。
- 在图谱上高亮匹配结果。
- 降低非匹配内容的视觉优先级，或采用其他不丢失上下文的提示方式。
- 选择搜索结果后聚焦目标节点。
- 同步选中状态和详情面板。
- 清空搜索后恢复正常图谱显示。

不要只过滤画布外的列表而忽略画布本身。

## 4.5 创建个人知识

默认使用上下文操作。

### Create Knowledge Node

从图谱工具栏进入，填写基本概念信息并确认创建。

### Add Personal Note

从节点详情进入，添加对现有概念的个人补充。

### Create Relationship

从起始节点发起：

1. 选择 Connect。
2. 选择目标节点（画布或搜索）。
3. 选择关系类型（如系统支持）。
4. 输入关系理由。
5. 确认保存。

保存前可以取消。

失败时保留输入草稿，不得留下与服务端状态不一致的成功提示。

### 数据类型边界

保留当前已实现的独立笔记节点，不强制将其迁移成新的节点附属笔记表。

如果底层已有支持附属笔记的数据结构，则优先复用；否则本轮可使用现有独立笔记节点，并通过清晰命名和交互关联改善体验。

不得仅因 UX 文案调整而改变节点存储类型。

# 5. Student User Flows

## Flow S01 — 首次探索

1. 用户进入 Knowledge。
2. 系统识别个人图谱为空。
3. 展示探索引导。
4. 用户进入 Explore。
5. 选择示例或已发布图谱。
6. 在图谱中选择概念。
7. 查看概念和关系。
8. 引用概念到个人知识空间。
9. 返回个人图谱并看到引用结果。

成功标准：无需教师账号、无需了解底层数据对象即可完成首次引用。

## Flow S02 — 日常知识探索

1. 用户打开个人图谱。
2. 搜索或选择节点。
3. 查看详情与关系。
4. 选中某条关系查看理由。
5. 继续探索相邻节点。
6. 图谱保持当前浏览上下文。

成功标准：无需反复返回上一级页面即可完成连续探索。

## Flow S03 — 个人知识补充

1. 用户选择已有概念。
2. 打开个人笔记或建立连接操作。
3. 编辑内容。
4. 保存。
5. 视图同步更新。
6. 刷新后已持久化内容仍存在。

成功标准：保存成功与失败都具有可理解的反馈。

## Flow S04 — 学习活动

1. 用户从概念、关系或公开图谱进入活动。
2. 阅读问题或案例。
3. 提交答案或执行原有交互。
4. 获得反馈。
5. 返回关联知识内容或继续其他练习。

成功标准：保留现有练习、案例与 Correction Lab 链接的语义。

# 6. Teacher Workspace Specification

## 6.1 职责边界

教师工作区独立于学生个人图谱，主要承担：

- 管理自己的图谱。
- 创建与编辑草稿。
- 编辑概念、关系、问题和案例。
- 预览内容。
- 保存、审阅和发布。
- 保留历史发布版本。

本轮重点重构教师的编辑流程和安全反馈，不强制将教师编辑器与学生浏览器合并为同一组件。

可以共享底层画布与纯展示组件，但不能混合角色权限及编辑状态。

## 6.2 编辑状态

至少区分：

- Clean — 当前内容无未保存变更。
- Dirty — 有未保存变更。
- Saving — 正在保存。
- Saved — 最近一次保存成功。
- Save Error — 保存失败。
- Review Pending — 当前保存修订未确认审阅。
- Reviewed — 当前保存修订已确认审阅。
- Published — 指定保存修订已发布。

这些状态可以通过现有数据和前端状态组合表达，不要求必须新增数据库枚举。

保存不自动代表已经审阅。

预览不自动代表确认发布。

## 6.3 未保存内容保护

当存在 Dirty 状态时，以下行为需防止无提示丢失：

- 切换图谱。
- 加载另一份草稿。
- 离开教师编辑页面。
- 触发会覆盖当前表单状态的其他操作。

可通过 Save / Discard / Cancel 选择完成。

浏览器刷新或关闭保护应遵循浏览器原生限制，不承诺能够自定义所有关闭提示。

## 6.4 复杂案例编辑

完整保存所有 claims、links 和现有模型字段。

对尚未开放编辑的字段实施原样保留，严禁仅用可见表单内容重建整个对象而丢失其他数据。

## 6.5 预览与发布

发布操作应针对已保存的确定修订版本。

当保存后内容发生变化，之前的审阅确认应失效或要求重新确认。

如果预览内容已过期，提示重新加载。

本轮不要求开发复杂逐页审阅追踪，但必须清楚区分“已打开预览”和“已确认审阅”。

# 7. Account, Local Mode & Data UX

## 7.1 账户入口

学生登录与退出不再占据个人图谱主内容区域。

统一放入全局账户位置或紧凑的账户操作入口。

## 7.2 Local Mode

在后端未配置的环境中：

- 继续提供现有静态示例。
- 保留浏览器本地数据能力。
- 显示明确的 Local Mode 标识。
- 禁止显示无法正常完成的账户提交操作，或以禁用状态解释原因。
- 不将本地数据标记为已同步。

## 7.3 数据持久化

现有本地存储键和服务端引用契约必须保持兼容。

本轮不自动迁移、清除或重置旧版记录。

对存储失败而退回内存的情况，应明确提示此时更改可能无法在刷新后保留。

## 7.4 空状态与错误状态

每个主要页面应覆盖：

- Loading
- Empty
- Error
- Unauthorized
- Unavailable
- Save Failed

错误提示必须与具体操作关联，并提供合理的恢复途径。

# 8. Technical & Data Compatibility Constraints

## 8.1 必须保留

- 七概念示例及其稳定 ID。
- Learning Path 的旧 URL 契约。
- Correction Lab 等跨模块链接。
- 公开图谱历史版本和直接访问地址。
- 教师所有权和私有草稿边界。
- 个人引用的来源 ID、版本及内容快照。
- `knowledgeV2`、`knowledgeStudyV2` 及现有 V1 兼容读取能力。
- 浏览器记录与账户数据的显式分离。
- 个人手动关系和节点坐标。
- 当前已实现的题目即时反馈及学习标记。
- 静态示例兜底机制。

## 8.2 实施约束

- 以当前项目静态页面、JavaScript、CSS 和既有 API 架构进行增量重构。
- 不因代码组织问题直接引入 React、Next.js 或新的全局状态库。
- 拆分文件时保持公共行为和数据契约稳定。
- 不依赖前端隐藏元素实现安全权限。
- 新的公开资源列表不得暴露教师私有草稿。
- 数据模型不支持的操作必须调整 UI 或单独设计后端增量方案。
- 必须先运行已有测试，建立真实基线。

## 8.3 组件职责建议

逐步将下列职责分离：

- Graph Canvas：节点、边和视口交互。
- Graph Data Adapter：数据加载与格式转换。
- Selection / View State：当前选择、搜索与详情面板状态。
- Personal Workspace：个人引用、笔记和连接操作。
- Public Learning Views：公开概念、题目、案例。
- Teacher Draft Editor：教师草稿编辑与发布流程。
- Account / Import UI：登录和显式数据导入。

这属于责任划分，不要求在首阶段强制实现对应数量的文件。

# 9. Implementation Phases

## Phase 0 — Baseline & Safety

实施前：

1. 确认工作分支和 commit。
2. 运行现有自动测试。
3. 识别当前部署与仓库提交差异。
4. 补充案例多 claims / links 的无损保存测试。
5. 修复已确认的潜在字段覆盖问题。
6. 修复关键保存失败状态恢复问题。
7. 完成未保存草稿切换保护。

**Exit Criteria:** 关键内容不会在无关编辑中丢失，现有测试通过。

## Phase 1 — Navigation & Workspace

1. 重组 Knowledge 导航。
2. 实现上下文 Empty State。
3. 将账户操作移出图谱主要内容区。
4. 提供 Explore 入口及最小公开资源浏览能力。
5. 保留原路由与深链接。

**Exit Criteria:** 新用户能发现公开知识、进入学习并返回个人图谱。

## Phase 2 — Graph Interaction

1. 统一节点选择与上下文详情。
2. 增加关系点击及关系详情。
3. 同步搜索和图谱高亮、聚焦状态。
4. 改造个人笔记与建立关系流程。
5. 完善节点切换、取消编辑和失败恢复。

**Exit Criteria:** 可在保持图谱上下文的情况下探索概念与关系，完成个人编辑。

## Phase 3 — Learning & Teacher UX

1. 恢复已有活动与练习入口。
2. 改善概念、案例和练习的学习导航。
3. 完善教师内容编辑和保存状态。
4. 明确草稿、预览、审阅、发布之间的状态。
5. 验证教师内容与学生引用数据的兼容性。

**Exit Criteria:** 教师发布和学生学习两个流程能够稳定完成。

## Phase 4 — Regression & Polish

1. 自动化测试。
2. 跨页面和跨模块链接测试。
3. 移动端布局测试。
4. 键盘可访问性测试。
5. 空态和错误恢复测试。
6. 已有浏览器数据兼容性测试。
7. 教师和学生权限边界测试。
8. 部署预览验证。

**Exit Criteria:** 无关键功能回退，无已知数据丢失路径。

# 10. Acceptance Criteria

## AC01 — 导航

用户能够明确辨别 My Knowledge、Explore 和教师工作区，不会将账户操作误认为知识编辑操作。

## AC02 — 首次使用

空个人图谱能够引导用户发现知识资源，并完成首次引用。

## AC03 — 节点探索

用户可以通过搜索和画布选择节点，打开节点详情，并继续访问关联内容。

## AC04 — 关系探索

用户可以选中一条关系，查看关系类型、方向、理由与来源归属。

## AC05 — 编辑状态

用户可安全创建或编辑个人内容；取消不提交，失败不伪装成功。

## AC06 — 教师数据完整性

编辑包含多条 claims / links 的案例后，未修改字段仍完整保留。

## AC07 — 草稿保护

教师在存在未保存内容时切换图谱或离开编辑流程，应获得适当保护。

## AC08 — 学习功能

`activities`、`practiceHref`、公开题目和案例的已有功能可被用户发现及访问。

## AC09 — 数据兼容

现有个人记录、教师发布版本、深链接、共享 ID 和跨模块链接保持正常。

## AC10 — 本地与服务端模式

本地模式不误导用户认为数据已同步；服务端模式中的身份和权限由服务端验证。

## AC11 — 响应式与可访问性

桌面端与移动端均能完成主要浏览任务；节点和关系有可用的替代选择方式，不依赖精确鼠标点击。

## AC12 — 回归测试

现有测试通过，新增关键交互和数据安全测试通过；未覆盖的后端流程明确列出未验证项。

# 11. Delivery Requirements for Codex

Codex 在实施前必须输出：

1. Current Code Mapping — 现有实现与目标规格的对应关系。

执行要求：

- 逐阶段实现，不得一次性重写整个模块。
- 优先复用现有功能，不随意删除。
- 每阶段执行对应测试。
- 不擅自改变本文件 D01–D07 的产品决策。
- 遇到规格与代码契约冲突时，说明冲突并提出最小修改方案。
- 不使用虚假的数据、假的持久化或假的后端成功结果完成验收。
- 未完成或未验证的功能应明确报告。
- 未经明确要求，不提交生产部署，也不执行破坏性数据库操作。
