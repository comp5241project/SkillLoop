# SkillLoop Knowledge Module — Architecture & UX Audit

审计日期：2026-10-22。审计对象：本地 `feature/knowledge-map` 分支，以及 [线上 Knowledge 页面](https://skillloop-zh.vercel.app/knowledge-map/) 的只读走查。本报告是后续产品设计与实施计划的依据，不代表已确定的重设计方案。

**证据标记**：**已确认**＝代码或线上界面直接支持；**推断**＝有代码依据，但影响尚未实测；**待验证**＝需要配置后端、测试账户或额外浏览器流程。本次未修改业务代码、数据库或部署；未登录、提交表单或创建浏览器记录。

## Current Information Architecture

从用户任务看，当前模块分为三层，而非按文件目录理解：

| 层级 | 页面与用户任务 | 职责边界 |
| --- | --- | --- |
| 个人网络 | `/knowledge-map/`：管理引用概念、私人笔记和手动连接 | 默认入口；数据存在浏览器或登录后的账户 |
| 公开学习内容 | `graph.html?graph=…` → `concept.html?graph=…&topic=…` → `question.html`／`case.html` | 教师发布后公开；七概念示例是该层的一份静态兜底内容 |
| 教师制作 | `teacher.html`：选择／创建图谱、编辑草稿、预览、发布 | 需要教师账户及后端；草稿不公开 |

账户管理没有独立页面：学生登录、退出和导入在个人网络顶部，教师登录在工作台顶部。个人页直接链接示例图谱和教师工作台；公开内容页的面包屑都返回“My network”。旧 `/knowledge-map/?topic=<id>` 由个人页重定向到示例概念页，供 Learning Path 既有链接使用。**已确认**：[路由契约](../../docs/DATA-CONTRACTS.md#L13)、[个人页入口](../index.html#L8)、[旧链接重定向](../personal.js#L4)、[跨模块链接](../../learning-path/script.js#L60)。线上 `.html` 地址规范化为带尾斜杠的路径，与 [Vercel 配置](../../vercel.json#L7)一致。

## Current User Flows

1. **学生探索与收藏**：个人页 → 示例公开图谱 → 选概念 → 概念页 → 练习或案例；概念页可“Reference in my network”，再回个人页查看引用。**已确认**：[公开页跳转与引用](../public-pages.js#L19)。线上已走通图谱搜索、选中概念、打开概念／练习／案例页；收藏未点击，以保持只读。
2. **个人整理**：个人页搜索并聚焦节点；创建笔记；连接两个节点；选中节点后编辑笔记、查看入向连接或删除。画布支持缩放、平移和拖动节点。**代码已确认**：[个人页逻辑](../personal.js#L39)、[画布实现](../network-core.js#L85)。创建及持久化效果**待验证**。
3. **账户切换**：登录后显示账户网络，浏览器记录不会自动上传；有本地节点时才显示显式导入按钮。退出后重新显示浏览器记录。**代码已确认**：[状态切换](../personal.js#L132)。线上部署显示“Browser-only mode”，账户同步流程**待验证**。
4. **教师制作**：登录 → 新建或选择图谱 → 编辑概念、关系、题目和案例 → 保存草稿 → 逐页预览 → 勾选已审阅 → 发布。**代码已确认**：[教师工作台](../teacher.js#L104)。线上教师页提示缺少 Supabase 配置，编辑与发布**待验证**。

### 具体功能实现

- **Graph Canvas**：一个 `Canvas` 类负责按钮节点、SVG 连线、缩放、平移、选中和可编辑模式下的拖动；三个场景共用。连线设为不可接收指针事件，没有直接点击边的入口。节点位置在 `set()` 时写回传入对象。[实现](../network-core.js#L85)。
- **节点详情**：公开图谱选中概念后显示描述及概念页链接；个人页区分引用节点和笔记节点，显示来源、可编辑文本、删除按钮及入向连接；教师页选中概念后回填表单。[公开详情](../public-pages.js#L42)、[个人详情](../personal.js#L61)、[教师详情](../teacher.js#L46)。
- **关系详情与编辑**：公开图谱按选中节点列出相邻关系文字；个人页只在目标节点的 Backlinks 列出入向边。教师可新增或删除关系，个人可新增或删除手动连接；两者都没有修改现有关系类型／理由的流程。[公开关系](../public-pages.js#L48)、[教师关系](../teacher.js#L55)、[个人连接](../personal.js#L106)。
- **节点／笔记创建**：教师“Add concept”生成 UUID 概念及预填课程文本；学生“Add note node”生成本地或账户笔记节点。创建入口均与图谱编辑页绑定。[教师创建](../teacher.js#L188)、[个人创建](../personal.js#L146)。
- **搜索**：个人、公开、教师三个场景均按标题／描述或笔记文本过滤画布下方列表；点击结果才聚焦画布节点。搜索不直接过滤或标示画布。[个人搜索](../personal.js#L39)、[公开搜索](../public-pages.js#L25)、[教师搜索](../teacher.js#L29)。线上以“testing”搜索已复核。

## State Management & Data Flow

**浏览器数据已确认**：`shared/storage.js` 使用 `skillloop.v1.` 前缀。`knowledgeV2` 保存个人节点和手动边，`knowledgeStudyV2` 保存自报学习标记；V1 `knowledge.references` 只作为初始本地引用读取，原键保持不变。[存储封装](../../shared/storage.js#L3)、[V1 适配](../network-core.js#L53)、[学习标记](../public-pages.js#L95)。存储失败时，封装退回当前页面内存，不能保证刷新后仍在。[存储回退](../../shared/storage.js#L21)。

**服务端契约已确认**：可选后端为同源 `/api/knowledge?op=…`。公开读取按 `graph` 和可选 `version` 取已发布 JSON；登录使用 HttpOnly Cookie。教师草稿按修订号保存，发布读取已保存修订；个人引用、笔记、连接和坐标分别通过 API／数据库函数写入。[API 分发](../../api/knowledge.mjs#L207)、[图谱校验](../../api/_knowledge-model.mjs#L30)、[数据库表](../../supabase/migrations/20261021000100_knowledge_backend.sql#L11)、[个人网络扩展](../../supabase/migrations/20261021000200_knowledge_network_v2.sql#L27)。静态示例仅在原示例图谱缺少可用发布时兜底。[加载逻辑](../network-core.js#L32)。

**版本语义风险已确认**：个人引用以 `graphId:conceptId` 唯一标识，并保存来源版本及标题／描述快照；数据库另存不可变发布版本。个人图谱的“教师关系”却每次从**当前公开版本**重新计算。因此来源页可指向历史版本，而个人图谱上的关系可能随教师新发布而变化。[引用快照](../../api/knowledge.mjs#L309)、[关系计算](../personal.js#L18)。其期望语义属于产品决策，不宜在重构时默默改变。

## UX / IA Issues（按严重程度排序）

| 严重程度 | 发现与证据 | 确认状态 |
| --- | --- | --- |
| 高 | **默认入口把空个人网络作为首屏核心任务。**新用户先看到账户表单和空画布，公开学习内容仅是顶部一条示例链接。[页面顺序](../index.html#L8) | **线上已确认**；对首次使用的影响程度属**推断** |
| 高 | **部署状态与可操作控件冲突。**线上明确提示账户后端未配置，但学生／教师登录表单仍显示可提交。公开示例可用，账户与教师工作台不可用。[学生状态](../personal.js#L199)、[教师状态](../teacher.js#L310) | **线上已确认** |
| 高 | **已有内容能力在新页面不可见。**示例包含关系判断 `activities`，概念含通往 Correction Lab 的 `practiceHref`；模型会校验它们，但 `public-pages.js` 未渲染两类入口。[示例活动](../data.js#L127)、[模型](../../api/_knowledge-model.mjs#L97)、[旧 UI](../script.js#L205) | **已确认** |
| 高 | **案例编辑可能丢失已有结构化内容。**教师表单只回填首个事实、首个解释和首个概念链接；保存时重建 claims，并重写首个链接的类型和理由，额外 claim 无法保留。[案例编辑与保存](../teacher.js#L83) | **代码已确认**；含多 claim 案例的实际损失**待验证** |
| 中 | **“关系详情／编辑”能力不足。**画布边没有点击入口；公开图谱只在选中节点后列出关系文字。教师和个人连接都只能新增或删除。[Canvas 边](../network-core.js#L173)、[教师关系](../teacher.js#L55)、[个人连接](../personal.js#L160) | **已确认** |
| 中 | **搜索只过滤列表，不过滤或标示画布节点。**用户须再点列表结果才能定位。[公开图谱搜索](../public-pages.js#L25) | **线上已确认** |
| 中 | **教师草稿切换缺少未保存改动保护。**`dirty` 控制发布按钮，但切换图谱直接加载另一份草稿；没有离开提示。[切换逻辑](../teacher.js#L181) | **代码已确认**；实际流程**待验证** |
| 中 | **预览与审阅不是逐页核验。**预览可显示当前内存草稿；保存后勾选框由教师自行确认，程序不记录哪些页面被预览。保存新版本后，已有 iframe 也不会自动更新。[预览／发布](../teacher.js#L260) | **代码已确认** |
| 中 | **个人页节点编辑失败时反馈与显示可能不一致。**账户笔记提交失败会恢复对象旧值，但文本框保持新值；拖动坐标写入失败只显示错误，不恢复画布位置。[笔记处理](../personal.js#L80)、[位置处理](../personal.js#L127) | **代码已确认**；触发条件**待验证** |
| 低 | **“Teacher workspace”与学生个人操作并列。**页面没有按角色区分入口；缺少已发布图谱的发现／选择入口，非示例图谱主要依靠分享链接。[个人页导航](../index.html#L10)、[教师私有列表 API](../../api/knowledge.mjs#L231) | **已确认**；是否需要公开目录属**产品决策** |

## Existing Features That Must Be Preserved

- 稳定的七个共享概念 ID、Learning Path 旧链接重定向，以及跨模块链接契约。[共享 ID](../../docs/DATA-CONTRACTS.md#L13)。
- 多教师、多图谱的所有权边界；私有草稿修订号、不可变发布版本和历史 URL。[数据库发布流程](../../supabase/migrations/20261021000100_knowledge_backend.sql#L97)。
- 静态示例兜底、公开图谱／概念／练习／案例的直接链接，以及来源事实与教学解释的区分。[加载兜底](../network-core.js#L32)、[案例页](../public-pages.js#L138)。
- 个人引用的来源版本和内容快照、私人笔记节点、手动连接、反向链接、节点位置、浏览器记录与账户记录分离、**显式**导入。[个人数据契约](../../docs/DATA-CONTRACTS.md#L52)。
- 概念自报学习标记与题目即时反馈；两者目前都不是服务器端成绩。[概念／题目逻辑](../public-pages.js#L95)。
- 数据中已存在但当前页面未暴露的关系活动题、`practiceHref`；教师侧还有创建示例图谱、归档／恢复题目和案例、私有 AI 来源搜索。[教师工具](../teacher.js#L66)。

## Refactoring Risks & Dependencies

1. **数据兼容**：不要把 `knowledgeV2`、`knowledgeStudyV2`、V1 `knowledge` 或 `graphId:conceptId` 键当成纯 UI 状态替换。导入要求来源图谱已在后端发布，线上当前浏览器示例记录未必能直接导入账户。[导入数据库函数](../../supabase/migrations/20261021000200_knowledge_network_v2.sql#L146)。
2. **链接兼容**：保留直接 URL 的 `graph`、`topic`、`question`、`case`、`version` 参数和旧 `?topic=` 路径；Learning Path 仍生成旧链接。[跨模块链接](../../learning-path/script.js#L60)。
3. **内容模型**：`pathRole`、`order`、`icon`、`activities`、`practiceHref`、案例的多条 claims／links 都在数据或校验层存在，当前教师表单未完整编辑这些字段。新编辑器需明确保留、呈现或迁移策略。[模型校验](../../api/_knowledge-model.mjs#L38)。
4. **权限与环境**：线上只证明静态示例路径；不能由此推断 Supabase RLS、教师所有权、跨设备同步或 AI 搜索在真实环境正常。[部署说明](../../docs/KNOWLEDGE-BACKEND.md#L42)。

## Recommended Refactoring Boundaries

- 先明确**个人空间、公开学习内容、教师制作、账户状态**四个用户任务的导航边界；示例作为公开图谱的一种来源处理。
- 分别界定 Canvas 选择／视口交互、公开图谱读取、个人数据适配、教师草稿编辑状态的责任；沿用现有静态页面和 API 即可，不需为分层引入新框架。
- 将概念、关系、练习、案例的**查看能力**与**编辑能力**逐项盘点，再设计界面，尤其先决定关系编辑和未暴露活动题的去向。
- 把草稿“已保存”“已预览”“已审阅”“已发布”作为不同状态描述，避免一个勾选框承载所有含义。

## Open Product Decisions

1. 新用户进入 Knowledge 时，首要任务应是探索公开内容，还是建立个人网络？空网络应如何引导？
2. 是否提供公开图谱目录？若不提供，非示例图谱只通过教师分享链接发现是否符合预期？
3. 个人图谱中的教师关系应固定在引用的发布版本，还是随当前版本更新？
4. 关系需要独立详情页、侧栏编辑，还是维持节点下的文字说明？教师与学生各能编辑哪些关系字段？
5. `activities` 与 `practiceHref` 是需要恢复的现有学习功能，还是保留数据但暂不展示？
6. 教师编辑多条案例 claims／links、概念路径字段时，应提供完整编辑能力还是受控的只读保留？
7. 浏览器记录导入账户遇到“来源未发布／历史版本缺失”时，应如何向用户解释并允许处理？
